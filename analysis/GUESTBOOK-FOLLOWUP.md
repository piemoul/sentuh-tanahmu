# Buku Tamu: bounded native UI and arrival boundary

Pinned native 6.1.5 static audit. Ledger: `analysis/recovered/guestbook-followup/flow.json` (`d0fc1e5e1a7f770001b15aed6ec2f4b60b43558256654e4a76f1d0ba55939238`). Independent verifier: `analysis/rea/verify_guestbook_followup.py`. Public labels: `analysis/recovered/guestbook-followup/public-copy.json`.

The actual home entry opens oBb6272. Its post-frame callback reads the locally stored sign-in model: a cached user opens the PC QR scanner; otherwise a chooser can supply an aCb662 before scanning. The chooser's population/ownership rules and the shared scanner's camera/permission lifecycle were not audited. No camera or QR value was used.

The complete QR parser requires the scanned String to **contain** `persuratan.atrbpn.go.id`. This is not exact URI-host validation. It splits the query and uses substring tests for `id` and `kd`, retaining their second `=`-separated values in nBb678. Both values must be nonnull; malformed delimiters can throw. There is no signature, time, coordinate, geofence or radius check in this bounded parser. This does not make a scanned identifier trusted proof of attendance, nor establish what the server verifies. No QR was fabricated or generated.

The form starts a separate GET through d288d8. Native read failures display “Maaf permintaan kamu belum dapat kami proses, cobalah beberapa saat lagi”; a null model displays a spinner. The nine displayed fields are name, NIK, phone, birth date, birthplace, KTP address, email, institution and purpose. Cached sign-in forwards only its NIK and email. The selected-user branch forwards the five fields proved by its serializer. These are distinct sources; no arbitrary browser-selected server identity is certified.

Aggregate validation tests null/raw empty values, NIK length below 16, and whether nonnull email contains `@`. No trim, exact 16-digit constraint, full email regex or date parse appears in the audited aggregate validator. Full shared input/keyboard/formatter semantics remain unclosed. “Simpan” sets busy, validates, and only then calls POST; the controller inverts the native service error bool and opens “Terimakasih / Buku Tamu Sudah Terisi / Kembali” on success. Read/transport/model construction is independently owned by `guestbook-service-followup`.

The official instruction explicitly says the form registers **kedatangan** and that an officer verifies the entries before a visitor card is obtained. Saving is therefore an arrival-record write, separate from reading office metadata. No GPS/device/geofence field is passed by this bounded form/controller, but that does not prove remote-arrival authorization or absence of enforcement elsewhere. Preserve legitimate office-issued QR and actual visit context; no fake attendance, location spoofing, automatic arrival POST or bypass follows from this audit.

Verification re-decodes 4,874 new and 442 inherited ELF instructions, 216 new pool bindings, 13 class records, 9 dispatch entries and 10 allocator headers. The `?` literal is separately bound to Blutter's escaped pool representation and its escape routine. No production/network requests, guestbook submissions, credential values, initializer execution, application changes or complete end-to-end parity are claimed. Disposal/stream-close, async ownership, current server behavior, QR authenticity and officer verification remain unclosed.
