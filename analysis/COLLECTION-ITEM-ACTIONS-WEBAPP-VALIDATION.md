# Validasi edit dan hapus item koleksi

Sumber 0220b4de92358f0e2d7bf1e83591ba4f392e4ec0b3ad6b8e35f552702dc3cc52 mengikuti [audit edit](COLLECTION-ITEM-EDIT.md) dan [audit hapus](COLLECTION-ITEM-DELETE.md). Form Edit Caption mengganti title, memakai nilai awal title??'', trim native, dan tidak mengirim nilai yang menjadi kosong. Nilai dikunci sebelum await; input tetap dapat diedit saat sibuk. Batal dinonaktifkan dan Simpan diganti indikator proses. Hasil normal sukses maupun gagal menutup dialog setelah await.

Sukses edit memakai list baris terkini dan mengganti semua ID yang cocok dengan clone delapan field: title menjadi caption dan groupId menjadi null, sementara subTitle tetap. Penghilangan groupId merupakan perilaku cache client native, bukan bukti penghapusan membership server. Root BERKAS tidak mendapat edit; kartu FEb root PERSIL serta seluruh tipe pada grup terpilih mendapat edit. Tidak ada GET atau perubahan cache grup/loaded flags.

Delete root BERKAS memakai konfirmasi tanpa frasa dari koleksi; PERSIL root memakai frasa itu. Controller mengambil snapshot baris sebelum await dan mencari ID pertama yang persis sama dengan row.id??''. Tidak ada kecocokan berarti no-op tanpa jaringan. Tipe hasil lookup pertama memilih endpoint PERSIL atau Berkas; sukses menyaring seluruh ID yang sama dari snapshot tadi, tanpa GET atau perubahan grup. Null-ID tidak disamakan dengan ID kosong pada predicate. Dialog menutup setelah hasil normal. Pelepasan dari grup tetap alur terpisah.

Tiga skema tambahan berada di luar corpus170 yang tetap byte-identik terhadap baseline rilis ini. PUT memakai multipart berurutan id,caption; dua DELETE memakai satu segmen String ter-encode, tanpa body/query/files. Exact HTTP200 dan yEb nullable bool/String/String diperlukan; field error:true tidak mengubah tuple sukses native. Konfirmasi, sesi, Origin, CSRF dan penyamaran log dipertahankan. Validasi panjang/path, aksesibilitas modal dan guard duplikasi/hasil terlambat merupakan adaptasi browser.
