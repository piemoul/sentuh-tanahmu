## Explicit browser adaptations

- Browser-owned camera Blobs, immutable form snapshots, declared WGS84 coordinate entry and local map return replace Android-specific storage/widgets/stack management. The final native plotting path uses the camera target; this does not establish a visit-geotag exemption.
- Coordinate text is the existing browser binary64 formatter preserving negative zero; shipped-engine float-to-text parity remains unproven. Filename and boundary RNG sources are browser-server adaptations.
- Ready local staging expires after 120 seconds, with one context per session, a 64 MiB aggregate retained-source-byte budget and the existing 25 MiB request/final-payload limit. Retired ready staging follows that TTL; no staged source bytes are persisted to disk.
- A branded dispatch marker distinguishes pre-dispatch `not_sent` from a transmitted request whose outcome cannot be confirmed. Ambiguous transport/response failures retain an unknown guard and never auto-retry. This deliberately reports uncertainty instead of interpreting a transport exception as proof of rejection.
- OSM raster and official Bhumi layering are the user's existing browser choice; synthetic browser tests redirect tiles locally and do not verify provider map acceptance or geospatial accuracy.
