# Antrian: kantor, lokasi dan ketersediaan loket

Alur baca prasyarat Antrian sudah diterapkan pada Docker lokal dan domain Cloudflare. Pengguna dapat membuka Mulai Mengantri, memilih kantor dan lokasi kerja, lalu melihat ketersediaan loket berdasarkan tanggal serta kalender kantor. Ini belum merupakan pemesanan antrean lengkap; Ambil Antrian tetap nonaktif. Tiga GET diaktifkan, sehingga katalog tetap 176 operasi dengan 80 aktif. Status enabled tidak membuktikan penerimaan produksi.

Sumber native yang digunakan tetap [booking reads](recovered/queue-booking-reads/flow.json), [office selection](recovered/queue-booking-selection-followup/flow.json) dan [date bounds](recovered/queue-booking-date-followup/flow.json). Verifier ketiganya lulus terhadap ELF dan pool yang dibekukan. Office dan lokasi mensyaratkan data nonempty serta mengabaikan error/message envelope; availability memakai error Boolean nullable dengan default true, dan menerima daftar kosong ketika false. Model integer membedakan token integer/double dan mempertahankan signed64 lebar sebagai teks desimal. String nullable dan urutan baris dipertahankan.

ID antrean `jyb.id` dipakai untuk filter lokasi. Kalender memakai `jyb.kantor_id` langsung, bukan decoder ciphertext milik jalur Kantor Terdekat. Browser hanya mengirim referensi kantor antrean ke endpoint kalender lokal; backend mengambil canonical ID dari cache respons yang dimiliki sesi. Browser tidak mengirim canonical ID bebas, origin, header, bearer atau identitas pemohon ke Directus. Pergantian kantor/refresh mencabut cache anak sebelum request baru; respons lama tidak mengisi pilihan baru. Duplikasi ID yang ambigu ditolak sebagai penjagaan web.

Pemohon memakai cabang profil sendiri dari account_summary yang dikenali, level 2/3 dan isIkd false. NIK hasil login bukan pengganti. Identitas tambahan yang perlu enrollment tidak dibuat dari input bebas. Preferensi kantor hanya memindahkan kecocokan canonical pertama; tidak memilih kantor secara otomatis. Placeholder tetap selected+disabled sampai pengguna memilih baris nyata. Lanjut mengikuti gate identitas dan teks kantor/lokasi nonempty.

Tanggal request diformat memakai hari lokal. Batas picker berasal dari waktu pembukaan dikurangi tepat 24 jam, tanpa upper bound. Tipe hari libur harus String '1' atau '2', bukan angka dan bukan aturan akhir pekan umum. Batas 365 hari hanya pencarian awal native, bukan maksimum tanggal. UI browser menggunakan input tanggal dan konfirmasi eksplisit; ketelitian milidetik, parser ISO ketat, pengambilan ulang kalender lintas tahun serta sinkronisasi tanggal request adalah adaptasi yang dicatat. Model pencarian awal holiday native diuji, tetapi widget HTML tidak diklaim identik dengan seluruh picker native. Kalender gagal ditampilkan sebagai ketidakpastian; tanggal libur yang ditolak kembali ke tanggal diterima. Hasil selalu mencantumkan tanggal ketersediaannya.

Total Antrian memakai jumlah_antrian_total; Sisa Antrian memakai jumlah_antrian langsung. Antrian Saat Ini memakai nomor atau '-' ketika null. Status hanya Buka untuk integer 1; flag teks '1' tidak dikoersi. Kedua tombol Ambil Antrian tetap nonaktif, termasuk saat respons menyatakan is_available=1. Tidak ada request booking, enrollment, OTP atau socket realtime.

Pengujian final: 1.206 tes Node, 1.190 pemeriksaan VM dalam 23 suite, dan 23 pemeriksaan browser desktop 1280×720 lulus. Review host menjalankan 20 probe independen; review backend delapan kelompok probe, termasuk lifecycle sesi, refresh auth dan batas trusted calendar. Fixture browser menjalankan 21 request sintetis gabungan draft/final; semuanya selesai tanpa request tak terduga. Pengujian produksi akun, identitas asli, OTP, booking dan kamera berjumlah nol. Pengujian mobile serta penerimaan server asli belum dilakukan.

Container sehat. Sebanyak 28 frontend dan 25 backend cocok dengan sumber; image tanpa bind mount/jaringan cocok pada 53 berkas; 28 frontend juga cocok melalui HTTPS publik. Restart backend mengakhiri sesi memori sehingga preview perlu refresh dan login kembali. Baseline 55 runtime, 27 ledger native dan 347 receipt historis dipertahankan. Percobaan awal dan temuan tanggal pada browser disimpan terpisah dari hasil final.

Audit OTP dan instruksi liveness juga bertambah: [OTP](DARING-OTP-FOLLOWUP.md) dan [liveness entry](DARING-LIVENESS-ENTRY-FOLLOWUP.md). Keduanya bukti statis, tidak mengaktifkan pengiriman atau menyatakan akun terverifikasi. Transform payload, cleanup/provider assurance, SDK kamera dan verifikasi akhir masih terbatas. [Matriks menu](WEBAPP-FUNCTION-COVERAGE-2026-10-20.md) mencatat 29 menu/38 route pada snapshot sebelum tiga read ini; Buku Tamu, pencarian Cari Bidang dan sejumlah alur lain masih belum selesai. Peta langsung detail Berkas tetap belum terikat. Geotag tanpa bukti kunjungan tidak diaktifkan. Goal keseluruhan tetap belum selesai.
