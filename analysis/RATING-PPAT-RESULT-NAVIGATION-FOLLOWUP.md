# Rating PPAT: normal result navigation

The normal returned-tuple path requests **pop until the first present route of the default global navigator**, then invokes the existing result-message dialog helper. It is not a one-pop return to Aktaku. The exact identity of that first route is not established by this bounded audit. No application file, catalog flag, API request, native execution, or production submission was changed or performed.

This extends [the frozen Rating UI proof](RATING-PPAT-UI-FOLLOWUP.md). [Source index](recovered/ratingppat-result-navigation-followup/source-index.json) and [verification receipt](recovered/ratingppat-result-navigation-followup/verification.json) bind the original 6.1.5 ELF, 18 new retained windows, seven retained dependency windows, 3,575 instruction occurrences, 62 decisive markers, pool references, metadata, and 24 complete claimed function bodies. Adjacent bytes in windows are not attributed to Rating.

Common helper `726368..726584` performs navigator lookups with `LZd=true` and delegates dialog creation to `d1c2b0`. This audit does not independently execute the helper, prove the old context remains usable throughout transition, identify barrier/backdrop behavior, or reconstruct the full push/observer/disposal framework.

There is **no explicit Aktaku read, list refresh, local rating-ready mutation, or cache invalidation in the complete local result caller, returned-tuple controller, dialog builder, or Tutup callback**. The controller's ordinary completion clears its busy subject and returns the tuple. The retained original Aktaku entry `8127a4..812898` starts navigation through `6ba6fc` and returns immediately, with no await/then return-refresh callback in that entry. These are bounded local absences; navigator observers, disposal, and other upstream lifecycle handlers may have effects and were not exhaustively audited. Do not invent an automatic refresh or claim globally that no refresh can occur.

For a browser implementation, the source justifies an explicit result path shared by ordinary true/false tuples, preserving the returned message. A named Aktaku refresh, success-only navigation, or one-pop-to-Aktaku behavior needs separate evidence or must be identified as a browser adaptation. Actual production Rating acceptance remains outside this static proof.
