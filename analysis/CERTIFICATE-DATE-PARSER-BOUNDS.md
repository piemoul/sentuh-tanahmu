# Certificate date parser: numeric fields, literals, and verification

This additive static followup narrows the remaining grammar questions in `CERTIFICATE-DATE-FLOW.md`. It inspects the same Sentuh Tanahku 6.1.5 ARM64 `libapp.so` (`bbc7f3bde07502916f00915afe55028a391efd57a5d47e5b30bd820aabd4a683`). No app execution, account, provider request, or runtime webapp change is included. The package version of the embedded `intl` library is still unidentified.

## Rules proved at the native handler level

- Numeric fields obtain an anchored digit match from all remaining input through `0xc71e3c` → `0xc720c4` → `0xc71ff4`. The ASCII digit matcher initializer at `0xc72718` constructs `^\\d+`. The parser advances by the matched length and parses the match as an integer. There is no numeric token-width cap in this path. Thus `MM`, `dd`, `HH`, `mm`, `ss`, `SSS`, and `yyyy` cannot be faithfully implemented as mandatory fixed-width regular-expression groups.
- Both `M` and `MM` go to the numeric month path: `0xe229d4` → class dispatch → `0xc76a60`, whose pattern-length branch uses numeric parsing for lengths other than 3, 4, and 5. All six configured alternatives use numeric months. Their day/hour/minute/second fields share the numeric helper above.
- Year parsing at `0xc71a60` stores the parsed year and sets the ambiguous-century flag only when the **pattern** length is two (`0xc71ac4`). Every configured year pattern is `yyyy`, so a two-digit input does not itself activate that flag. `0x72c900`–`0x72c920` returns the stored year immediately when the flag is false. Do not introduce a 1900/2000 pivot for these patterns.
- Fractional seconds (`S`) call the same integer parser. Closure `0xc7285c` stores the parsed integer unchanged at DateBuilder offset `0x3f`; `0x72d038`–`0x72d05c` verifies 0–999. No decimal-fraction scaling or mandatory three-character width appears here. For example, a parsed integer `1` represents one millisecond, not a tenths-of-second conversion.
- Twelve-hour parsing (`h`, `0xc71b1c`) maps parsed integer 12 to 0 (`0xc71b70`–`0xc71b80`) and otherwise preserves the parsed number. PM adds 12 later. Verification uses the resulting hour range 0–23, rather than a separate parsed `h` range 1–12. The actual format oracle should cover inputs such as `0`, `12`, and `13` rather than imposing conventional clock rules in a port.
- `a` loads the locale AM/PM symbol list and invokes a class-dependent text matcher. It sets the PM flag only when the returned symbol index is 1 (`0xc72808`–`0xc72818`). The strict matcher (`0xc77314`) gathers prefix matches and throws when none exists. Its subsequent selection prefers the longest symbol; an equal-length later match replaces the earlier choice. The loose wrapper (`0xe22ba4`) transforms candidate symbols with the `0xc772c8` closure and returns `-1` on the caught format-error branch. Consequently, a missing AM/PM symbol can leave the default AM flag unchanged in a loose parse, provided the other fields and full-consumption check succeed. The exact Indonesian symbol table is not exported by this followup.
- Strict literal parsing calls `0xc71910`: read the configured literal's length and require exact string equality; mismatch throws. Loose literal parsing calls `0xc7298c`: skip whitespace, consume the configured transformed literal only if it matches, then skip whitespace again. This permits an omitted separator; it does not replace a separator with arbitrary punctuation. The whitespace routine at `0xc72a44` advances while a one-character substring is entirely removed by its string-trimming helpers. The exact Unicode trimming table was not exported.
- Dispatch entries bind both literal classes (CID 1417/1418) to strict `0xc718e0` and loose `0xc7295c`; both numeric classes (CID 1415/1416) reach strict `0xc71a30` and loose `0xc72b78`. The loose numeric wrapper delegates to the same numeric handler. Quoted `T`/`Z` are therefore literal fields, not timezone conversions. Upper/lowercase semantics should be taken from the actual Dart/`intl` parser, rather than an invented ASCII-only transform.
- Both strict and loose top-level paths verify full consumption and DateBuilder fields before returning. The native DateBuilder checks month 1–12, effective hour 0–23, minute/second 0–59, milliseconds 0–999, and equality of parsed day/year to the constructed DateTime's day/year. Calendar overflow is therefore rejected rather than silently accepted as the next month. The original local-DateTime construction evidence remains applicable.

## Exact evidence and limits

New bounded ranges and ELF-bound hashes are listed in `analysis/recovered/certificate-date-parser-bounds/export.json`, `export-edges.json`, and `export-finish.json`. Their additive exporter is `analysis/rea/export_certificate_date_parser_bounds.py`. Every retained instruction is decoded directly from the original ELF. Existing `range-00c71a30.asm.txt`, `range-00e226b0.asm.txt`, `range-0072cf58.asm.txt`, `range-0072be88.asm.txt`, and `range-0089dc2c.asm.txt` provide the previously retained callers and verification sequence. The dispatch identities come from the existing `certificate-detail-dispatch/dispatch-addresses.tsv`, at register indices CID minus `0xf81`, `0xf89`, `0xfed`, or `0x1000` as used by their callers.

`range-00e22ba4.asm.txt` is an exploratory range that also contains subsequent unrelated instructions after the wrapper ends at `0xe22cec`; only `0xe22ba4`–`0xe22ce8` supports the claims above. Likewise, tail instructions after a reviewed function's return are not evidence for that function. This followup does not attribute those adjacent functions to date parsing.

Still unproved here are the exact embedded `intl` package release, all Unicode case/whitespace and locale digit-table contents, an exhaustive accepted-input grammar, local timezone/DST behavior at unusual historical dates, machine-integer overflow edges, and the complete DateTime representable-year boundary. Reusing the matching Dart parser and testing a pinned input matrix is stronger than inventing JavaScript fixed-width regular expressions. A source-matched Dart oracle would still be an oracle for the selected source/runtime, not evidence that the APK itself executed those inputs.
